# CLAUDE.md

Guidance for AI agents working **on this repository**. For using the sandbox, see `README.md`.

## What this repo is

`ai-dev-sandbox` installs a hardened devcontainer into any project. Its purpose is to make
running an AI coding agent unattended — auto mode, or `--dangerously-skip-permissions` — an
acceptable risk, by enforcing a boundary the agent cannot alter.

The central mechanism is a **network airlock**: the container's network is closed by default,
reachable only to `api.anthropic.com`, and opened deliberately from the host for short
windows. The agent can re-apply the firewall but never widen it.

## Repo layout

```
install.sh              # installer: preflight, config parsing, rendering
bin/ccnet               # host-side control (up/rebuild/shell/status/open/close/down)
core/                   # copied verbatim into every project — NEVER templated
  init-firewall.sh      #   the firewall and airlock logic
  net-open.sh           #   root-only, not in sudoers
  net-close.sh          #   root-only, not in sudoers
  zshrc                 #   convention, not security
presets/php-mysql/      # one stack: templates + defaults
templates/              # devcontainer.json + the two config examples
```

## The one rule

**`core/` and `bin/ccnet` carry the security guarantee. Do not weaken them.**

These invariants must hold after any change. Each exists because its absence was an actual
bug at some point:

1. **Sudoers grants exactly one command** — `init-firewall.sh`, nothing else. `net-open.sh`
   and `net-close.sh` must never be added.
2. **`init-firewall.sh` reads its mode from a root-owned file** it cannot itself change.
   That is what makes granting it via sudo safe: re-running it re-applies the current mode.
3. **The firewall applies from the compose `command`**, not only `postStartCommand`. The
   latter runs solely under the devcontainer CLI/VS Code; a plain `docker compose up` would
   otherwise leave the container with no firewall while the mode file still said `closed`.
4. **`ccnet status` verifies the live iptables chain**, not the mode file. A status command
   that cannot detect its own control being absent is worse than none.
5. **No Docker socket** is ever mounted into the container.
6. **`cap_add` is `NET_ADMIN` and `NET_RAW` only.** Never `SYS_ADMIN` — it would permit
   remounting filesystems.
7. **The allowlist is baked into the image**, never bind-mounted. A read-only bind gives no
   protection, because the same file is visible read-write under `/workspace` and `:ro` only
   blocks writes through that mount point.
8. **The firewall fails closed.** Any abort forces the mode to `closed` and retries once;
   a second failure leaves everything blocked.
9. **`install.sh` parses `sandbox.conf`, never sources it.** The file lives inside the
   project, which the sandboxed process can write; sourcing would let it execute commands on
   the host at the next install.
10. **Every scalar from `sandbox.conf` is validated** before interpolation. Those values land
    in a Dockerfile that the host then builds, so an unvalidated one is a route to arbitrary
    build content. Note the checks are **globs, not regexes**: a positive pattern like
    `[A-Za-z0-9._-]*` is useless, because `*` matches any string — it accepted
    `PHP_VERSION=8.4-apache AS evil`. Test for a *disallowed* character instead:
    `case "$val" in *[!A-Za-z0-9._-]*) die ;; esac`.

If a change appears to require breaking one of these, that is a design problem — raise it
rather than working around it.

## Conventions

- **Bash**, `set -euo pipefail`, POSIX-ish. No Python or Node in the install path.
- **Comments explain *why*, not *what*.** Most of the non-obvious lines encode a bug that
  was hit in practice; say which, so nobody "simplifies" it back.
- Generated files carry a `GENERATED by install.sh` header.
- Template placeholders are `@@UPPER_SNAKE@@`, substituted by bash parameter expansion —
  not `sed`, so values never need escaping and multi-line blocks work.
- `SANDBOX_VOLUMES` is the single source for **both** the Dockerfile `mkdir` list and the
  compose volume list. Never let those diverge.

## Adding a preset

1. `presets/<name>/` with `Dockerfile.tmpl`, `docker-compose.yml.tmpl`, `defaults.conf`.
2. Support the same placeholders; at minimum `@@MKDIR_LIST@@`, `@@VOLUME_MOUNTS@@`,
   `@@VOLUME_DECLS@@`, `@@USER_UID@@`, `@@USER_GID@@`, `@@EXTRA_ENV@@`.
3. Copy the airlock block from `presets/php-mysql/Dockerfile.tmpl` **verbatim** — the
   `COPY`/`chown`/`chmod`/sudoers/allowlist/mode-file sequence.
4. Keep the compose `command` pattern: firewall first, fail on non-zero, then the service.
5. Run the full verification below before considering it done.
6. Document its provisioned versions in the README requirements table.

## Testing a change

Reading the design does not find these bugs — the ones that mattered were all found by
running it. Install into a throwaway project and work through the suite:

```bash
SCRATCH=/tmp/sandbox-test
rm -rf $SCRATCH && mkdir -p $SCRATCH/public && cd $SCRATCH && git init -q
./install.sh --project $SCRATCH
cd $SCRATCH && ccnet up
```

**Start-up** — output must include `Verified: CLOSED (Anthropic only)`.

**Blocked and allowed**, as the sandbox user:

```bash
curl --connect-timeout 5 -s -o /dev/null https://example.com   # must fail
curl --connect-timeout 5 -s -o /dev/null https://github.com    # must fail when closed
curl --connect-timeout 5 -s -o /dev/null https://api.anthropic.com  # must succeed
(echo > /dev/tcp/db/3306)                                      # must succeed
dig +short @8.8.8.8 example.com                                # must fail
```

**Escalation — the important part.** All must be refused:

```bash
sudo -n /usr/local/bin/net-open.sh          # denied by sudoers
echo open > /etc/claude-net-mode            # permission denied
echo x >> /usr/local/bin/init-firewall.sh   # permission denied
echo x >> /etc/sandbox-allowlist            # permission denied
ls /var/run/docker.sock                     # must not exist
sudo -n -l                                  # exactly one command
sudo -n /usr/local/bin/init-firewall.sh     # ALLOWED, must re-apply CLOSED
```

The last one is the critical assertion. If it reopens the network, the design is broken.

**Round trip**: `ccnet open` → registries reachable; `ccnet close` → blocked again.

**Every start path**: stop the stack and start it with plain `docker compose up -d`, which
skips `postStartCommand` entirely. The firewall must still apply. This regression shipped
once and was invisible — `ccnet status` reported `closed` while everything was reachable.

**Status honesty**: flush the rules as root and confirm `ccnet status` reports `DANGER` and
exits non-zero.

**Idempotency**: re-run `install.sh` and confirm `sandbox.conf` and `allowlist.txt` are
preserved while generated files are refreshed.

## Known trade-offs

Do not "fix" these without understanding why they are as they are:

- **`/24` expansion** in the allowlist is wider than the domains listed. Exact-IP
  allowlisting does not survive CDN rotation — package installs fail minutes after opening.
  Correct tight filtering needs a proxy, not iptables.
- **The workspace bind is the real repository.** Not fixable without giving up the bind
  mount. Mitigated by keeping push on the host.
- **`zshrc` is convention, not security.** Projects may replace it.
- **Changing the allowlist requires a rebuild.** That cost is deliberate; see invariant 7.
- **IPv6 is blocked wholesale, not allowlisted.** The allowlist is IPv4-only (ipset
  `hash:net`, A records), so v6 gets policy `DROP` plus loopback. Note `ccnet status`
  inspects only `iptables`, so it would not notice if the v6 rules were absent.
- **Apache is backgrounded** so an httpd error does not take down the sandbox. A
  healthcheck surfaces the failure instead, since otherwise a dead Apache is invisible.
